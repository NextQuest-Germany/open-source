# Contributing

Create a short-lived `feat/`, `fix/`, `docs/`, or `chore/` branch from `main` and open a pull request. Keep changes focused and describe validation, risks, and rollback. Request review from the repository owner; team-based ownership will follow repository permission setup.

Run the project-specific build, tests, lint, and security checks once a technology stack is selected. The initial Repository hygiene workflow checks whitespace and conflict markers only; it does not certify application correctness or deployment readiness.

A human must review changes before merge. This is the working policy; enforceable branch rules still need configuration. Do not push credentials, production data, or unreviewed deployment changes. Report suspected security issues privately using SECURITY.md.
